# 菜单栏入口缺失诊断

## 实机结论

菜单栏图标问题仍未解决，不能将恢复按钮执行成功、`isVisible == true` 或 Release 构建通过当作实际显示成功。

- 用户确认已安装版 1.0.5（20）点击“恢复图标”后仍无图标。
- 已安装应用的辅助功能授权有效。其可执行文件 SHA-256 保持为 `221dcf9276c787d119e22407e56723fd4767fa4416d6c9c05e0ad46a3c95438d`。
- macOS 26.7.3 的 ControlCenter 日志明确记录 `Starting to track blocked host`，对应 `com.zhiyan.dynamicisland-DynamicIsland.MainControl`。
- 系统设置 → 菜单栏 → 允许在菜单栏显示，应用列表中没有灵动岛。退出并重新打开系统设置后仍然如此。
- 现有诊断探针读到主入口 AX 位置 `x=7..31, y=1168, h=24`；候选版的 AppKit 窗口为 `{{0, -22}, {38, 22}}`，位于菜单栏之外。单凭状态项存在不能确认可见。
- 本机有内建刘海屏及外接屏，收纳开关关闭。诊断期间未移动其他应用图标。

## 已尝试的恢复

通过 Finder 正常启动、重新登记当前安装的 LaunchServices 信息、重启一次 ControlCenter、修复本应用的 `Visible` / `VisibleCC` 显示记录，均未解除系统阻止。没有重置整个控制中心，没有修改受保护的系统配置或 TCC 数据库，也没有更换应用 bundle ID。

## 源码改进及验证范围

- 状态项先以零宽度创建，配置固定标识、图像和动作后再显示，减少默认 `Item-0` 与正式标识之间的注册时序问题。
- 恢复时隐藏并移除旧项、解除旧标识和强引用，下一轮主循环再修复显示记录和重建，避免旧场景清理覆盖新记录。
- 兼顾旧版与 macOS 26 的应用侧显示记录；常规启动保持用户已有位置，只有主动恢复时重置位置。
- 使用系统支持的可移除行为；恢复期间禁用重复点击。
- 设置中新增系统菜单栏设置入口，恢复后检查位置并给出反馈，不默认宣称恢复成功。
- 测试包含迁移、用户位置保留、显式恢复、无关配置保留、实际故障坐标和多屏负坐标。

`zsh Scripts/test-menu-bar-entry.command` 的 10 项检查通过。设置页浅色、深色及未授权状态共 16 张离屏渲染完成，通用页已检查新增入口的布局；这些渲染不代表菜单栏图标可见。

候选版 1.0.5（21）编译并实际启动，但仍被系统阻止，未通过菜单栏可见性验收。候选版未覆盖安装；验证结束后已重新运行 `/Applications/灵动岛.app` 1.0.5（20），启动日志确认 `accessibility=granted`。

当前剩余问题是本机系统阻止状态及缺失的应用开关。重新登录或重启系统后的恢复效果尚未验证；不能将这些操作描述为已确认的解决方法。未发布安装包或 Sparkle 更新。
