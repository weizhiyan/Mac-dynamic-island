# 刘海音乐展示与性能扩展

Written against: `3c855d58573e8e292f83fb4a1886843763800d97`（当前工作区包含未提交的既有修改，执行前以当前文件为准）

## 目标

在真实刘海的基础上横向增加一小段空间，收起态展示当前播放器头像和一组随播放状态变化的白色波纹；展开态在内容区顶部增加“音乐摘要 + 系统性能摘要”双卡，底部已完成的音乐卡片和性能卡片保持原样，作为后续扩展区域。

本方案只规划本次新增展示和交互，不重新设计设置页，不引入渐变流体，不改变副屏行为，也不把底部双卡迁移或删除。

## Evidence chain

- Surface: `IslandWindowController` 管理的收起/展开灵动岛窗口，以及 `IslandRootView` 的展开内容。
- Problem: 当前收起态只有黑色刘海，没有播放内容反馈；展开态只有底部媒体/性能卡片，顶部没有即时摘要。
- Design evidence: 用户提供的参考图和当前已验收的黑色刘海、底部等高双卡布局。
- Owner: 窗口几何与动画归 `Sources/DynamicIsland/Window/IslandWindowController.swift`；播放器状态归 `Sources/DynamicIsland/Managers/MediaPlayerStore.swift`；展开内容归 `Sources/DynamicIsland/Views/IslandRootView.swift`；刘海测量归 `Sources/DynamicIsland/Utilities/NotchDetector.swift`。
- Scope and affected surfaces: 主屏刘海的收起态、鼠标悬停展开态、播放器绑定/播放/暂停/无曲目/播放器未启动状态。
- Uncertainty: Spotify AppleScript 当前能稳定提供歌名、艺术家和播放状态，但不保证提供专辑封面与实时音频振幅；必须提供图标/静态波纹回退。

## Design language

- Audited surface: macOS 菜单栏顶部的黑色灵动岛及其展开面板。
- Design sources: 当前 SwiftUI 卡片、现有 `SettingsStore` 动画参数、`NotchDetector` 的系统辅助区域测量、用户参考图。
- Documented decisions: 黑色主体；底部音乐卡片与性能卡片等高、8pt 间距；播放器由用户绑定；展开/收起使用可调时长和 cubic-bezier。
- Governing owners and consumers: `MediaPlayerStore` 是唯一播放器状态源；`SystemMetricsStore` 是唯一 CPU/内存状态源；`NotchDetector` 是唯一主屏和刘海几何源；`IslandWindowController` 是窗口生命周期和过渡状态源。
- Explicit exceptions: None documented.

## Design decision

### 1. 收起态：刘海横向扩展的紧凑音乐层

收起态仍以黑色刘海为主体，左右各增加约 `14pt` 的内容空间，保持测得的刘海高度。左侧放圆形或连续圆角的当前音乐头像，右侧放固定数量的白色短线波纹；波纹只在播放时运动，暂停时冻结为低幅静态状态，停止/无曲目时隐藏内容并恢复基础刘海宽度。

头像优先使用播放器提供的当前曲目封面；Spotify 无法提供封面时使用播放器图标，再退回音乐符号。无论哪种来源，都必须保证左侧永远有稳定的占位，不因异步加载导致刘海跳动。

波纹第一阶段是“播放状态驱动的视觉反馈”，不是实时音频振幅。使用固定数量的线条或柱条，只更新 `transform`、透明度或高度参数，不触发布局；不申请麦克风，不读取系统录音，也不把波纹放进 `gooeyContainer.filters`。

### 2. 展开态：顶部摘要双卡，底部双卡原样保留

当播放器已绑定时，在现有内容顶部插入一行摘要卡，位于应用网格之前：

- 左卡：封面/播放器图标、歌名、艺术家，以及唯一的播放/暂停按钮。点击暂停/播放继续调用 `MediaPlayerStore.togglePlayPause()`；播放器未启动时沿用现有逻辑，由用户点击播放后启动播放器。
- 右卡：复用 `SystemMetricsStore` 的 CPU 和内存百分比，做成比底部性能卡更紧凑的摘要。
- 两卡高度固定为现有 `64pt`，中间保留 `8pt`，与底部卡片的视觉语言一致。
- 当前 `MediaPlayerCard` 和 `SystemMetricsCard` 继续位于底部，控件、尺寸、文案和交互均不改。本次顶部摘要不是替换，也不是把底部卡片移动到顶部。

未绑定播放器时不增加摘要行，现有展开布局保持不变。已绑定但没有曲目时，左卡显示明确的空状态，右卡仍显示性能摘要，不能渲染空白占位。

### 3. 主屏和尺寸规则

所有紧凑态和展开态都继续使用 `NotchDetector.mainScreen()` 返回的系统主屏。鼠标位于副屏时不创建、不迁移任何窗口。没有刘海的主屏只显示已有灵动岛行为，不显示紧凑音乐层。

用 `NotchDetector.current()` 的 `frame`、`anchor` 和 `screenFrame` 计算紧凑 bounds：

```text
compactWidth = clamp(max(settings.compactWidth, notch.frame.width + 28pt), 24pt, settings.topBarWidth - 24pt)
compactHeight = notch.frame.height
compactX = notch.anchor.x - compactWidth / 2
compactY = notch.frame.maxY - compactHeight
```

坐标以 AppKit point 为准，不能把 backing scale 当作额外宽度。紧凑层上下边界必须裁在 `compactY...compactY + compactHeight` 内；顶部不画额外横线，不向屏幕外溢出。圆角取当前形状设置与 `compactHeight / 2` 的较小值，不能为了波纹重新发明一套刘海形状。

播放器播放状态只影响紧凑宽度和内容显隐，不影响展开态的应用网格宽度。曲目从播放中变为暂停时保持当前紧凑宽度，避免用户看到宽度跳变；曲目清空或播放器解绑后才回到基础宽度。

## Reuse

- `MediaPlayerStore.shared.track`、`playbackState`、`isBusy`、`togglePlayPause()`：不得在视图中重复查询 AppleScript。
- `SystemMetricsStore.shared.cpuUsage`、`memoryUsage`：顶部摘要和底部卡片使用同一数据源。
- `NotchDetector.current()`、`mainScreen()`：不得根据鼠标所在屏幕重新定位。
- `SettingsStore.expandDuration`、`collapseDuration`、`expandTimingFunction`、`collapseTimingFunction`：紧凑层和黑色主体共享同一过渡参数。
- Exemplar: `Sources/DynamicIsland/Views/IslandRootView.swift` 的底部双卡和 `Sources/DynamicIsland/Window/IslandWindowController.swift` 的 `transitionID` 中断保护。

如果当前 `MediaTrack` 无法携带封面，应新增可选的 artwork 字段或独立缓存模型；不能让播放器视图直接持有脚本、网络请求或图片缓存。

## Implementation phases

1. 几何与窗口层：先只接入主屏刘海 bounds、紧凑宽度/高度计算和独立透明内容层。用静态占位验证主屏、副屏、无刘海屏和顶部裁切，确认不影响现有展开动画。
2. 播放内容与波纹：接入 `MediaPlayerStore` 的 track/playbackState，完成头像回退链和播放/暂停/停止状态；再加入固定槽位的合成层波纹。此阶段不改展开内容和底部双卡。
3. 展开顶部摘要：新增顶部双卡并更新展开高度；复用播放器和性能数据源，确认未绑定播放器时高度与原版一致，已绑定时底部双卡完全保留。
4. 过渡与回归：把紧凑层接入现有 `transitionID`、presentation path 和 cubic-bezier；验证快速反向、减少动态效果、播放器轮询刷新及窗口销毁/重建，最后运行构建、渲染脚本和签名检查。

## State machine

```text
unavailable / unbound
  -> black notch only

track available + paused
  -> expanded compact width + static low-amplitude waveform

track available + playing
  -> expanded compact width + animated waveform

track cleared / player unbound
  -> hide compact content, return to base width

hover enter
  -> compact media fades/scales out while island expands

hover leave
  -> expanded content fades out while compact media returns
```

所有异步回调都必须检查当前 `transitionID`、`isEnabled` 和目标状态。播放器轮询更新歌名或艺术家时，只更新头像/文本，不重新创建窗口，不重置波纹相位。

## Validation

- Product: 绑定 Spotify，播放一首歌；收起态看到左侧头像和右侧跳动波纹，暂停后波纹冻结；悬停展开后顶部左卡能播放/暂停，右卡能看到 CPU/内存。
- Product: Spotify 未启动时点击顶部播放，沿用现有自动启动逻辑；拒绝自动化权限时显示明确错误，不反复启动应用。
- Interface: 检查短歌名、超长歌名、无艺术家、无曲目、播放器关闭、解绑播放器、暂停、停止和错误状态；摘要卡和底部双卡均不溢出或重叠。
- Interface: 在 1x/2x backing scale、不同刘海宽高和无刘海主屏上检查高度、圆角、顶部裁切；副屏移动鼠标不改变位置。
- Interaction: 连续快速悬停进出至少 30 次，并在展开中反向收起，确认无闪烁、卡死、重复波纹层或旧内容回调。
- Performance: 播放时只更新合成层属性；“减少动态效果”开启后波纹停止；不出现麦克风/录音权限请求。
- Repository: `swift build` -> 成功；`git diff --check` -> 无空白错误；`zsh Scripts/test-notch-rendering.command` -> 几何和状态检查通过；`codesign --verify --deep --strict Build/灵动岛.app` -> 成功。

## Scope

- Inherit: 当前播放器绑定、Spotify 自动化、性能采样、主屏固定、现有动画曲线和底部双卡。
- Verify: `IslandWindowController` 的窗口层级、`SettingsStore` 的展开高度计算、`AppGrid` 的排序和悬停触发区域。
- Exclude: 真实音频振幅、麦克风或虚拟音频设备、远程音乐服务登录、底部卡片改版、设置页新增波纹微调项、渐变流体效果、多屏独立灵动岛。

## Stop conditions

- 如果 Spotify 或目标播放器无法提供稳定封面，停止扩展远程网络抓取，使用播放器图标回退，并把真实封面列为后续需求。
- 如果 `NotchDetector` 在目标机器上无法得到有效 `topInset` 或辅助区域，停止自动扩宽并回退到当前 `compactWidth`，不要猜测屏幕坐标。
- 如果新增内容必须修改底部双卡的布局才能放下，停止并重新确认范围；本方案不允许通过压缩或删除底部卡片解决高度问题。
- 如果波纹需要录音权限或引入虚拟音频驱动，停止第一阶段实现，保留播放状态驱动的静态/伪动态波纹。

## Design documentation

实现并由用户验收后，再把最终采用的紧凑态尺寸规则、波纹回退策略和顶部摘要卡边界记录到项目工作记录；在验收前不把本方案写成已确认的长期设计决策。
